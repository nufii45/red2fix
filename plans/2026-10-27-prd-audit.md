**Feasibility answers**
1. **Refs.** `copytree` keeps `.git` (it only ignores pycache/venv, `main.py:267`), and the `:ro` mount doesn't block the copy. But `demo/repo` isn't a git repo (`ls -a`), so `run_local.sh:10` can't supply branches. You need a separate demo git repo, plus `fetch-depth: 0` in Actions.
2. **Diff leak.** `_resolve` allows any path under the root, including `.git/` (`tools.py:29-34`). That exposes `COMMIT_EDITMSG`, `logs/HEAD` and ref names (packed objects are binary, so mostly safe). The bigger leak is the spec itself: a PR body often quotes the change. Keep the working tree on base during LOCALIZE/REPRODUCE and fetch head afterwards.
3. **Stale caches.** Low risk: `-p no:cacheprovider` (`tools.py:84,98`), `PYTHONDONTWRITEBYTECODE=1` (`Dockerfile:8`, `Dockerfile.swebench:11`), and pycache is excluded on copy. A real gap: if base and head both time out, both return `{"<suite timed out>"}`, which cancels to "no new failures" (`tools.py:102`, `main.py:173`). Compiled extensions (astropy) aren't rebuilt between checkouts.
4. **No result.json.** `out.mkdir`, `prepare`, `LLM()` (a missing `NEBIUS_API_KEY` raises KeyError at `llm.py:19`) and reading the issue all sit *outside* the try (`main.py:280-288`). SIGKILL, OOM and a docker timeout also leave no result. Every caught error becomes `aborted` with an `error:` prefix (`:303-309`); there is no `error` status yet.
5. **Secrets.** Yes. `--env-file .env` (`run_local.sh:9`, `bench/run.py:43`) and `_run` passes the full env to pytest (`tools.py:37-40`). There is no `--network none`, so network is on. Test code can also write `/out` (`Dockerfile:10`), which means it can forge `result.json`/`review.json`.
6. **amd64.** Nothing assumes macOS. The bench hardcodes `linux/amd64` (`bench/run.py:36,43`), which runs natively on `ubuntu-latest`. `score.sh` needs `uvx` (setup-uv).
7. **Bench mode.** `pick.py:48-56` doesn't store `r["patch"]`. Add it, pass `--head-patch` into the container, apply it after BASELINE with `tools.apply_patch`, and label each review gold or failed. Failed patches come from `SWE-bench/experiments`, which hasn't been checked yet.

## Part C: What the PRD gets wrong or leaves out
- **The gate can be forged.** DECISIONS:8 says "the sandbox never holds a GitHub write token". FR-2 runs PR code in a job that has `statuses: write`, and `actions/checkout` stores the token in `.git/config`. The PR's tests can also overwrite review.json. Separately, same-repo PR authors already have write access and can POST a status themselves. §10.6/§10.7 overstate what the gate guarantees.
- **The spec is self-certifying.** When the spec is the PR description, the author writes both the claim and the fix, so ✅ only means "does what the author says". Acceptance criterion 6 depends on the LLM review, not on executed proof.
- **§10.2 delimiters don't exist.** The issue text goes into prompts raw (`main.py:115,123`, `prompts.py`).
- **Guards vs review mode.** `check_patch` blocks test edits, which legitimate PRs make. A PR that *deletes* a failing test lowers head failures and passes FR-6. You need a "test removed/skipped on head" check.
- **ARCHITECTURE.md is stale** (FastAPI, SQLite, Serverless Jobs, publisher), and only partly superseded. The v2 pivot, the Ultra review route and the Action-based publisher aren't in DECISIONS.md.
- On the bench, regression is scoped to the hidden test files (DECISIONS:21), not the full suite. §11 should say so.

## Part D: Verdict

**Top 5 risks**
1. **Forgeable gate** (Q5, Part C). Fix: state the threat model as "catches wrong PRs, not malicious collaborators". Use `persist-credentials: false`. Run the review with `permissions: {}` and post from a second job. Say this in the README.
2. **Bench never run, real cost unknown, gold patches not stored**, and 40 reviews × up to 1200 s under emulation at `-j 2` is about 6.7 h. Fix: gold-only, 10 instances, run Wednesday morning, ideally on an amd64 Actions runner.
3. **Fail-open spots**: garbled VERIFY_RED passes (`main.py:155`), the timeout sentinel cancels (`tools.py:102`), setup crashes leave no result (`main.py:284-288`). Fix: explicit `true`, treat sentinels as failures, wrap setup in the try, and have the Action map missing/invalid review.json to `error`.
4. **Schedule**: about 39 h of work against about 20 h available.
5. **Hard limits aren't hard** (`llm.py:19,51`, `tools.py:16`). Fix: `OpenAI(timeout=60, max_retries=1)`, plus `timeout-minutes: 15` on the job.

**Effort:** about 39 h for "New for v2" (including demo repo, README and video) vs about 20 h available. That's 2× over.

**Cuts, in order:** suggest-fix (−3h) → failed-patch half, and gold on 10 instances, not 20 (−4h) → dashboard verdict card (−3h) → FR-11 to SHAs + verdict only (−1h) → auto-merge (status only) → linked-issue spec (PR body only, capped at 🔶). That leaves about 26 h, still tight. The desktop pet isn't in the repo, so cutting it saves nothing.
